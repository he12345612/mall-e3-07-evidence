# E3-07 录屏讲解稿（约 90 秒）

本次选的是 E3-07：无效地址更新清空已有默认地址。调用入口是会员地址控制器的 `update`，它进入 `UmsMemberReceiveAddressServiceImpl.update`。规格要求：当前会员的地址 ID 不存在，或者地址属于其他会员时，返回 0，而且不能发生任何写入。有效地址设为默认时，仍然保留先清原默认、再更新目标的顺序；`defaultStatus` 为 null 时仍按 0 处理，原事务声明不改。

先看 `missingDefaultTargetDoesNotWrite`。当前会员是 101，目标是 999，并且请求设置默认。改前日志显示 6 项测试中 2 项失败，Errors 和 Skipped 都是 0。失败原因不是环境问题，而是原服务在确认目标是否存在之前，先把会员 101 的默认地址清零，之后目标更新 0 行。另一个失败覆盖地址属于其他会员的情况。

最小修复在服务第 46 行：使用原有的“当前会员 ID 加目标地址 ID”更新条件先执行 `countByExample`。如果计数为 0，就直接返回 0，所以无效目标不会清默认，也不会更新目标。我没有先更新目标再清默认，因为第二次清默认会把刚设置的目标又清掉。

原来的断言没有放宽，仍然是验证 `updateByExampleSelective` 从未调用。改后同一组 6 项测试全部通过，Failures、Errors、Skipped 都是 0。有效地址设为默认时，测试还验证了先写 0、再写 1 的顺序，并确认两次条件都带当前会员过滤。

最后看 JaCoCo，目标方法行覆盖 17/17、分支覆盖 6/6，方法内没有未覆盖项。但这个证据只证明真实服务加 Mapper 替身下的行为，不证明真实数据库事务、HTTP 认证链、并发删除或并发唯一默认。
